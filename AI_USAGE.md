# AI Tool Usage Disclosure

Assignment condition: AI tool use is permitted and expected. Undisclosed use is not
permitted. I am able to explain and modify every component in this repository.

## Tools used

**Claude (Anthropic)** — used interactively throughout, as a design interlocutor and
implementation assistant.

## What it was used for

| Area | Use |
|---|---|
| Schema review | Field-by-field audit of the v1.0 contracts against the Part One metrics, identifying which metrics were computable, partially computable, or not computable |
| Schema design | Drafting the v1.1 contract changes (A1–A8) and the confirmation-event schema |
| Part One | Drafting and revising definitions, metrics and limitation statements |
| Case review | Auditing the clean suite; the seven defects in `docs/case_review_findings.md` were surfaced through this review |
| Migration | Drafting `docs/migrate_v11.py` |
| Repo scaffold | Directory layout, stub contracts, configs, Makefile |

## What I decided

Every design decision was mine, made after argument rather than accepted by default.
Decisions I took against the assistant's initial recommendation include:

- Keeping §4.1 named "Retrieval recall @ K" rather than renaming it to reflect that
  retrieval is fixture-bound — the assignment lists it as a required metric under that
  name, and the caveat belongs in the limitation text.
- Collapsing "overreach on the core recommendation" to decision-relevance (Option 1)
  rather than adding a `core_claim_criteria` field (Option 2, the recommendation).
- Placing the parser/preprocessor in the evaluation framework rather than the system
  under test, which forced the annotate-only, never-repair boundary.
- Deferring the claim-coverage check to the preprocessor rather than the harness.

## Verification

- Every schema change was validated against the existing case data; results are in
  `docs/case_review_findings.md`.
- The migration is a reviewable script with an explicit patch table, not a hand edit, so
  every change is attributable.
- No result in this repository is generated by an AI tool and reported as a measurement.
  Responses in `results/responses/simulated_v1.jsonl` are a declared simulated fixture,
  recorded as `response_source: simulated_fixture` in the run config.

## Not used

No AI tool was used to fabricate results, citations, evidence, or claimed model
capabilities anywhere in this submission.
